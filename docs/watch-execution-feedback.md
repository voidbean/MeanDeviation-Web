# 盯盘成交反馈与通知去重

## 使用入口

右下角「盯盘」通知中心：

- **记录成交**：填写实际价、股数、本动作计划总股数、费用和实际时间。
  只用于尚未在本系统记账的真实成交，不是券商下单。方向来自独立的计划动作。
  股数小于计划总股数时为部分成交，后续可继续录入；累计达到总股数即完成。
- **暂不执行15分钟**：稍后重新观察并提醒，不表示成交。
- **忽略本次**：本轮持续成立期间不提醒，条件解除并连续确认后才重新布防。
- **今日停用**：明确停用对应计划动作，不由 AI 或价格恢复自动重新启用。
- **撤销最近成交**：回滚关联账目后可重新记录，原成交保留在审计表中。
  只能按逆序撤销全账户最近的盯盘成交；其后持仓、现金或受影响执行状态发生变化时拒绝自动回滚。

风险提醒不提供普通「稍后／忽略」屏蔽；用户仍可明确确认「今日停用」。
只调整今日提醒；历史未记账的实际成交允许按原计划当日时间补录，必须核对当前账目。

## 状态与账务

- 行情状态 `state` 与执行状态 `execution_status` 分离：pending / partial / completed / disabled。
- 已读仅清除未读标记，未反馈仍为「执行情况未知」。
- 动作 `action`：entry（首次建仓）、add（补仓）、reduce（减仓）、exit（退出）、cancel、observe。
  旧规则迁移时从文案兼容推断，新计划显式生成；补仓不是首次建仓的无限重复。
- 成交、持仓、现金、交易日志、执行状态由一个 `BEGIN IMMEDIATE` 事务提交。
- 买入更新加权成本（包含输入费用）并减少现金；卖出减少股数、增加扣费后现金，剩余持仓成本保持不变。
  这是一套本地账务口径，不表示券商可用资金、可卖数量或实际成交回报。
- 完成首次买入后停用同日同股票其他待执行首次建仓动作；独立补仓动作不受影响。
  全部卖出后停用同日同股票原持仓补仓、减仓和退出动作。
- 已有明确持仓时不再触发首次建仓；明确空仓时不触发持仓专属动作。
  不凭这些变化伪造任何成交记录。
- `watch_executions` 保存唯一请求编号、原始成交参数、前后账目快照及撤销时间。
  同一请求重试不会重复记账，同请求号不同参数会拒绝。
- 已关联的交易日志禁止在复盘页面直接改价、改量或删除，需经撤销流程处理。
- 有执行反馈的同日计划不会被重新生成覆盖；改价和盘中校准也不会重置完成状态。

## 去重与时序

- 每个规则保存最后处理的分钟快照；同一分钟多次轮询不累计确认次数。
- 分钟缺口、午休等不连续时间会清零连续确认计数。
- 未处理的普通机会再次触发时合并到该规则当前同类提醒，显示重复次数和最近更新时间，不反复弹窗。
- 合并提醒保留首次触发价格、时间，最新价在消息正文和影子审计中；不要把首次价格误当当前报价。
- 风险规则解除后再次成立仍可发出新提醒，不被机会提醒合并机制屏蔽。
- 通知中心每分钟回补最近 50 条（包含状态更新），SSE 相同 ID 更新原卡片。

## 边界

本功能不连接券商，不推断未反馈的成交，不校验交易所可卖数量，也不自动修复外部手动改账。
录入前必须核对本地持仓和可用现金。旧提醒被覆盖而原规则已不存在时不能用于成交入账。
表单在网络结果未知时保留原请求重试；不要另开表单重复录入同一笔成交。

重启应用自动迁移数据库。验证使用临时数据库与模拟 UI，不修改真实持仓、不下单。
