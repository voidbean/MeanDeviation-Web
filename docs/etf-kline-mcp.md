## 显式采集（不会随网页或 MCP 自动启动）

仅在服务器确认权限后手动运行。以下是操作说明，不表示已部署执行：

```bash
# 在服务器实际项目根目录运行；根 .env 复用已有 TUSHARE_TOKEN，无需新增鉴权项
uv run python -m scripts.collect_etf_klines --code 588170.SH

# 可先指定独立临时库验证；MCP 默认仍读原业务库，二者不是自动联通
uv run python -m scripts.collect_etf_klines --code 588170.SH --db /tmp/etf-validation.db

# 只有明确需要且权限已核实，才主动开启持续采集；Ctrl-C 停止
uv run python -m scripts.collect_etf_klines --code 588170.SH --loop --interval 90
```

- 默认只采一次。`--interval` 为每轮完成后的等待时间，至少90秒；同端点调用至少间隔65秒，单轮可能超过一分钟。
- 数据库全局租约防多进程并发采集；完成后全局90秒冷却。它不是多租户采集调度器。
- 一个 `--loop` 进程记住被拒绝的端点，不再发该端点的其他频率请求；修正权限后需人工重新启动。不会用新频率绕过拒绝。
- 日线窗口600自然日，分钟窗口120自然日。长停牌、接口截断或缺失不能保证 SMA233：返回缺口/样本不足，不能补零或跳过缺失假装连续。
- 盘中日线仅取前一交易日已发布的官方日 K；15:02后可取当日历史发布值。暂不构造盘中日 K。
- 盘后若历史端点已覆盖当天完整分钟网格，就不额外请求实时端点，不因缺少不再需要的实时权限而否定完整历史数据。
- 仅新建/更新 `etf_kline_cache`，不写旧行情表、持仓、策略或监控表，不执行主服务迁移。
- 每个标的一次原子发布全部周期、原始 K 线、因子与日历。失败周期保留仍在窗口内的旧数据并标记错误，其他成功周期仍可用；不会把旧值标成刚抓到的新行情。
- 输出仅含枚举错误和样本数，不包含凭据或原始异常。部分失败退出码为1；不能只看有 JSON 输出就认定全成功。
  `collected`仅代表抓取并发布成功，不代表数据已稳定、复权因子已齐或均线可用；分析前仍必须检查 MCP 的 `analysis_ready`。

## 时间、收线与复权

- 返回时区固定 `Asia/Shanghai`，时间戳带 `+08:00`，上游标签按**区间结束**解释。
- 60分钟结束网格：10:30、11:30、14:00、15:00；15分钟为上午09:45–11:30、下午13:15–15:00，共16根，不跨午休造 K。
- 日历以 `trade_cal` 为准。周末/节假日不是缺口；交易日应有但缺失的区间明确报告，不能擅自判断为停牌后跳过。
- `bars` 仅含确认收线数据。至少结束90秒后有一次抓取；实时分钟还需两次相同 OHLCV 观察、相隔至少30秒。修订后重置稳定计数。
- **只等 MCP 读取时间过去不会把旧的盘中抓取升级成收线。** 当前未结束区间为 `forming`；已结束但尚无闭合后抓取为 `awaiting_close_verification`；未稳定为 `awaiting_stability`。
- 历史端点已发布且结束90秒后的标准区间作为历史闭合依据；仍需实际有权限样本验收端点标签含义。额外09:30/集合竞价等非标准标签保留但隔离，并使该周期 MA/分析未就绪，不静默删除来凑网格。
- 三周期共用同一份已证实最新 `fund_adj` 因子日期作前复权锚点：`qfq_price = raw_price × 当日因子 / 锚点因子`。
- 当日因子未发布时，**不把昨日因子冒充今日因子**：当日分钟标记 `factor_missing`、价格及 MA 为 null，留存 raw 供审计。这可能使盘中分析未就绪，即使行情权限已开；需后续核验实际因子发布时间，不能承诺只开分钟权限就一定满足盘中需求。
- 因子更新后完整重算各周期，不拼接不同复权基准。SMA只用确认、连续、同一锚点的收盘价；缺口后重新积累窗口。

## MCP 调用与分页

使用现有 HTTPS `/mcp` 和 Bearer/OAuth 配置，无需新增权限或改 Tunnel。

```json
{"code":"588170.SH","period":"D","limit":60,"closed_only":true}
```

读取顺序：先 D 判断日线背景，再60min，最后15min细化数据，不在工具中制定买卖规则。
第一响应的 `snapshot_id` 应传给后两次调用；若返回 `snapshot_changed`，从 D 重新读，不能混用两个发布批次。

参数：

- `period`：`D` / `60min` / `15min`；`limit`：1–500，默认300。
- `start_at` / `end_at`：可选 `YYYY-MM-DD` 或带时区 ISO 时间，边界含端点。日期按上海全天解释；不接受无时区的时分秒。
- 默认最近 N 根，页内升序；用 `next_cursor` 向历史翻页，不重叠。翻页时其他参数保持相同。
- `warmup_bars`：本页之前最多232根，用于复算本页第一根 SMA233；不计入 `limit`，不受查询起点裁掉。warmup 自身的 MA 留空，避免声称未提供更早上下文的 MA 可复算。
- `closed_only=false` 仍不混入主 `bars`，仅额外返回最多100根 `unconfirmed_bars`；全部数量见 `unconfirmed_count`，最近一根见 `latest_unconfirmed_bar`。
- `forming_bar` 严格只指当天尚未结束区间，不把等待验证/稳定的已结束区间也称为 forming。

关键字段：

| 字段 | 含义 |
|---|---|
| `as_of` / `actual_range` | 本页实际确认数据时间/范围；空范围为null |
| `source_as_of` / `source_analysis_ready` / `source_stale` | 整个缓存序列的状态，与截取的本页分开 |
| `analysis_ready` / `stale` / `missing_reasons` | 只有最新连续 SMA55、无质量错误且覆盖应有末根才 ready；历史页/空页不能冒充当前可分析 |
| `page_ma55_ready` / `ma233_ready` / `source_ma233_ready` | 本页末根55/233及源末根233是否有足够连续样本；233不足不等于已有55也无效 |
| `expected_as_of` / `gap_count` / `gap_examples` | 日历要求的最新确认区间与缺口；实例最多10条 |
| `source` / `factor_source` / `fetched_at` / `collected_at` | 来源与时间；`generated_at`只是读取响应时间 |
| `snapshot_id` / `adjustment_anchor` | 整标的同一发布批次、同一复权基准 |

库/表/缓存缺失返回 `missing`，范围无确认数据返回 `empty_range`；不是0价格、不是自动补抓。
`permission_denied`、`rate_limited`、`factor_missing` 等均通过 `missing_reasons` 显式暴露。
MCP 始终 `mode=ro`、`query_only=ON`，不调用采集器、不建表、不触发旧的 lazy-create K 线读取。
