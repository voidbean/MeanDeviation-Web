# 55线监控（独立观察通道）

## 使用

个股分析页的「【55线】实时形态监控」点击开启。每只股票单独订阅，默认关闭；重启保留订阅与事件去重记录。停止后不再产生新事件（已经发出的消息无法撤回）。

第一版实时通知范围是 **日线背景 → 60分钟回踩转强**。日线新趋势和15分钟图表仍属于历史研究，不冒充实时信号。通知中心、SSE和 `scripts/watch_notify.py` 共用原有 `watch_events.id`；接收脚本未修改。

55线提醒醒目标记 `【55线】`，只表示规则来源，不表示经过验证的胜率，不创建交易计划、委托或成交记录。服务端拒绝对该类提醒提交成交/交易动作反馈。

## 数据与复权

- 独立线程、SQLite跨进程租约、轮询订阅股票；每次完成后全局至少间隔90秒，多个股票轮流处理。订阅越多延迟越大，本版不是全市场实时扫描器。
- 每交易日首次采集官方 `daily` 和 `stk_mins(freq=60min)` 历史，按窗口原子替换，修正旧数据，不使用旧的复权缓存拼接价格。
- 优先 `rt_min_daily(freq=60MIN)` 获取当天累计分钟K线；权限不足时降为 `rt_min` 逐根积累。缺失历史K线时等待下一轮官方历史回补，绝不用报价快照补OHLC。
- 原始K线按股票/周期/时间持久化，保留来源与采集时间。均线由同基准前复权收盘序列计算；公式 `raw * 当日因子 / 基准日因子`，日线和分钟统一采用当天因子基准。
- 必须包含当天复权因子；缺失时等待，不假定今天没有除权。成交量额不复权；股票日线的手/千元转换为股/元，分钟直接采用股/元。
- 旧快照保留期从7延长到90自然日，仍是近似报价历史，不参与55转强确认。

## 确认与防误报

- 60分钟只接受10:30、11:30、14:00、15:00边界，收线后至少90秒，并至少两次采集到一致OHLCV且间隔30秒。多次一致是保守稳定性检查，不保证数据提供商以后不修订。
- 交易日历验证整个参与计算的窗口；日线/分钟缺口、停牌或额外09:30记录均暂停确认，不擅自删掉开盘记录来凑均线。
- 分析始终使用本交易日之前的已收盘日线背景；当日未收线分钟不进入计算。历史图表依旧截至昨日。
- 首次合格分析只建立水位，启用前形态不补推。重启不重复；关闭再开启重新建立基线。
- 只推送最新已收线K线上的新事件，超过收线10分钟的过期信号不补推。数据修复、断网恢复不刷历史通知。
- 事件去重键、通知记录、水位在同一个SQLite事务内提交，随后发布SSE。SSE丢失可由原有HTTP轮询接收；不承诺操作系统桌面通知恰好投递一次。
- `ma55_event_keys` 留存完整形态依据与规则版本。`watch_events.rule_id=0` 专用于不关联执行规则的策略观察，UI不显示成交按钮，原有盘后收益归因排除该类型，避免复权价与旧报价混算。
- HTTP增量通知改为取最早未读的一批，避免消息积压超过分页大小时直接跳过旧ID。

## 旧日线修正

`fetch_history.py` 不再给不支持复权的 `daily` 传 `adj='qfq'`。股票和ETF都显式读取因子；缺失/重复/非正因子均取消写入。整只股票所有已存日期必须被覆盖，禁止只更新最近60天造成混合基准。价格类技术指标先失效，再由后续因子采集填充。

CLI每次执行，在修改数据库前通过SQLite backup API产生 `.qfq-时间戳.db` 备份。备份失败则不继续。单股数据完全验证后才原子落库；超过单次安全上限或历史日期覆盖不全需要另做分段迁移。本次开发**未执行生产历史重写**；下一次运行历史采集脚本才生效。55监控独立于旧 `daily_records`。

## 当前验证与限制

2026-09-16实测当前Token的 `rt_min_daily` 返回权限不足，降级 `rt_min` 实测返回一根15:00标准K线，9月15日/16日复权因子覆盖校验通过；尚未在真实盘中完成端到端信号投递验证。模拟测试覆盖采集、稳定性、日历/因子阻断、首次基线、持久去重、通知共用链路。应先对少量股票开启观察，确认页面持续显示正常已收线时间，再考虑扩大范围。

强风控默认是“数据不够就不确认”，不是把降级数据包装成高置信信号。严格窗口校验可能因为停牌或历史接口边界差异长期停在待确认；需核验官方数据后再放宽，而非绕过校验。
