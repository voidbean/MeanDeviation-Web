# 次日计划：技术上下文与影子验证

本阶段只采集与对比，不将新条件升级为买入硬门槛，不自动下单。
原价格规则的触发、风险提醒仍然有效；提示中的“原规则确认”不等于量价联合确认。

## 数据与时点

- 生成计划和 10:00 / 13:05 / 14:35 校准共用 `technical_context`。
- 日 K：最近 30 条已收盘 OHLC、成交量（股）、成交额（千元）。
- 日量比较：最新已收盘日成交量 / 此前 20 日均量，必须 21 日量数据齐全。
- MACD：复用本地 MACD(12,26,9)，柱值为 2×(DIF−DEA)，最多使用 120 条收盘价，至少 35 条。
  不混用分钟 MACD 或未收盘日线估算值；返回数据日期、计算来源与样本数。
- 当日 15:00 前不使用当日日线；执行某日计划时只使用该日之前的日线。
  全部来自本地已存数据，不会为生成计划额外请求行情接口。
- 分时：最近 30 个快照、累计量、当日累计 VWAP，以及近 3 分钟均量 / 此前 20 分钟均量。
  必须有 24 个连续快照，其中第一个只作时间区间起点，避开启动时累计量污染。
  缺分钟、跨午休、基准为零时，该量比为 null，而不是零或“缩量”。
- 日线缺失、MACD 样本不足或距离执行日超过 7 个自然日时，MACD 影子条件为“数据不足”。
  7 日仅是保守的陈旧数据检查，不代替交易日历或停牌判断。

## 结构化规则

每条规则新增 `conditions`（最多 3 项），所有项按 AND 汇总；允许的字段：

| metric | 含义 | value 范围 |
|---|---|---|
| volume_ratio_3m_20m | 近3分钟均量/此前20分钟均量 | 0.1–20 |
| price_vs_vwap | 当前价/当日累计均价 | 0.95–1.05 |
| daily_macd_hist | 已收盘日线 MACD 柱 | 仅 0 |

`op` 仅允许 `gte` / `lte`。不支持的指标、NaN、重复指标或非法阈值会拒绝整份计划，
不会静默丢弃条件后覆盖原计划。风险规则不允许添加这些条件。

```json
{
  "conditions": [
    {"metric": "volume_ratio_3m_20m", "op": "gte", "value": 1.5},
    {"metric": "price_vs_vwap", "op": "gte", "value": 1.0}
  ]
}
```

这里的阈值是配置示例，不是经过回测的推荐交易参数。
金叉、背离等未实现的形态只能作为背景或人工待核验，不能声称已自动验证。

## 查看与对比

- 次日草稿展示具体条件；今日计划展示每项满足、未满足或数据不足及检查时间。
- 实时推送及持久化提醒附上影子摘要，明确不阻塞原规则。
- `watch_rules.shadow_result_json` 保存最近一次结果。
- `watch_shadow_checks` 每条规则、每个分钟快照保存一条审计记录：实际值、阈值、
  条件状态、原规则是否命中、是否发出原规则确认提醒，以及当时的规则副本。
- `legacy_confirmed=1` 且影子 `status=unmet/unknown` 的记录，可用于检查新条件
  与旧提醒之间的分歧。当前只评估当时各条件，不模拟另一套连续确认状态机，
  也不据此声称收益得到改善。
- 表内不自动清理数据；长期运行需关注数据库体积，后续按实际保留周期归档。

## 启用及兼容

1. 重启应用时 `init_db()` 自动迁移，现有计划不被改写。旧规则条件为空，显示“未配置”。
2. 历史库过去未保存真实成交量，新列 `daily_records.vol` 默认 null。
   下次运行历史采集会补齐采集窗口内的量；需要更长历史时按项目原有 `--backfill` 方式执行。
   不用成交额或复权均价倒推出所谓“真实成交量”。
3. 重新生成并检查、启用计划，才会获得 AI 编写的结构化条件。
4. 本轮不自动重启运行中的服务、不调用真实 AI 生成计划，也不自动回填付费行情。
5. 影子技术数据读取失败会显示“数据不足”，不得压住原风险提醒。

附带修正：分时均价改为当日累计成交额 / 累计成交量，原先误用最后一分钟均价。
这会纠正以“分时均价/黄线”为阈值的原规则，属于原有数据口径修复。
