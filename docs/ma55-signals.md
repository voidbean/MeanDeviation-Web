# MA55历史信号 v1

## 范围

`services/signals55.py` 是无网络、无数据库写入的确定性历史形态引擎。
个股页读取或刷新K线缓存时附带 `analysis`，展示状态、理由、依据、失效条件，
最近五个历史事件，并在图中标注事件。返回至多100个事件，`event_count`为总数。
只在事件恰好发生于末根历史K线时设置 `signal`；旧事件单独列出，不冒充当前信号。
版本：`ma55-history-v1`；参数来自冻结的 `Rules`，修改规则应升级版本。

**不是收益回测、胜率、仓位建议、实时提醒或下单功能。** 未接入AI提示词、批量扫描
或原有盯盘规则。15分钟仍只展示图表。

## NEW_TREND（日线）

同一根已完成日线同时满足：

- MA5 > MA10 > MA20；三条MA均高于3根日线前（用比例变化展示斜率）。
- 收盘高于MA20和MA55。
- 前一根收盘 <= 当时MA55，本根收盘 > 本根MA55。

日线趋势一旦不再成立，旧突破不再供下级回踩使用。60分钟上级背景要求最近20根
日线之内出现过仍有效的NEW_TREND。此选择比“曾经突破过”更严格，为待回测规则。

## PULLBACK_ENTRY（日线 → 60分钟）

严格按时间顺序逐根推进：

1. 仅取当前60分钟K线日期**之前**最近一根日线作为背景（15:00那根也不使用当日日线）。
2. 上级日线满足上述趋势与近期突破要求。
3. 60分钟从MA55下方/等于MA55上穿，建立本轮形态。
4. 后续另一根60分钟收盘至少达到当根MA55的1.01倍，确认离线。
5. 再后续K线低点进入MA55的[0.98, 1.005]倍，且高点至少达到0.995倍。
6. 首次回踩成交量/此前20根60分钟均量 <= 0.8；缺失、零量不能冒充缩量。
7. 回踩当根或其后3根内，收盘 > MA55×1.002、收盘 > 开盘、收盘 > 前收，记为转强。

突破、离线和首次回踩不能是同一根；回踩和转强可以是同一根收盘确认。
“收回MA55”本身也可能构成上穿，不能因此把正在确认的回踩重置成新突破。
每轮只产生一个事件；之后若重新上穿，可建立新轮次，但必须重新完成离线与回踩。
本版不识别恐慌放量假跌破。量比尚未校正日内成交量季节性。

### 失效 / 过期

- 日线背景失效、缺少日线背景、分钟数据中断：清除正在等待的形态。
- 突破后低点低于MA55×0.98，或连续两根收盘低于MA55：失效，不以放量为必要条件。
- 尚未确认的突破超过40根60分钟K线：过期。
- 首次回踩超过3根后仍未确认：过期，不随反复触碰延长窗口。
- 历史已确认事件保留作审计，但当前状态可变为失效；事件不等于仍然有效的交易建议。

## 压力与失效价位

展示60分钟MA55、回踩以来已知低点。
上方参考压力只从**高于当前收盘价**的60分钟MA233和此前20根60分钟最高价选最近值。
MA233仅在有233根连续标准60分钟K线时参与参考。没有候选就留空，不造止盈价。
不比较不同复权基准的价格，也不使用未来确认的波段拐点。不输出仓位或盈亏比承诺。

## 数据保护与局限

- 今天及未来的K线不进入历史信号。时间须严格升序，重复、非有限价格、无效OHLC
  或MA会阻止确认。足够的MA数值不能替代足够的K线样本。
- 60分钟要求日线与小时线股票、前复权基准一致；缺少日线时提示先获取日线。
- 标准60分钟结束时刻为10:30、11:30、14:00、15:00。额外09:30记录不擅自删除，
  因为删除后原有SDK MA已不再对应新序列；此类数据会中断连续计数、阻止确认。
- 午休和正常跨日不视为缺口；漏一根分钟K线，或根据日线发现漏了整个交易日，
  会重置形态。重建至少55根连续标准60分钟K线后才重新允许判断。
- 上级日线距分钟线日期超过7个自然日时阻止确认（节假日可能保守拦截）。末根
  K线距分析日超过7个自然日时明确警告旧历史状态，但不抹除过去事件。
- 尚未引入独立交易日历与停牌表，无法证明日线及分钟线都同时漏掉的整天数据。
  同时也未证明分钟接口的时间标签与特定交易软件一致，因此只作为历史研究。
- 依赖当前前复权缓存。决策只访问当时及以前的K线；但SDK价格四舍五入和后续
  复权基准变化仍可能改变边界结果，不应宣称严格的逐时点收益回测。
- 所有参数是初始假设，未通过收益回测优化，不计算“匹配度=胜率”。

## 来源标识与后续推送接入

分析结果携带 `strategy_source: ma55`、`strategy_label: 55线规则`；每个确认事件还
携带 `rule_version` 和 `title`（如 `【55线】60分钟 · 回踩转强`）。页面用高对比度
来源徽章、逐条事件徽章以及图表“55”标记突出规则出处。来源不表示高胜率，
不依据消息包含“55”就给其他策略贴标签。

已检查现有监控：`services/monitor.py` 支持持久化后SSE推送，
`scripts/watch_notify.py` 支持桌面通知、游标去重与补漏。但当前监控是分钟快照
价格条件，事件关联watch_rules及成交反馈，不能将其“连续N分钟确认”当作
60分钟K线收线，也不能把历史策略事件直接塞入可执行买卖规则。

下一阶段可复用通知传输通道，先提供观察通知：
1. 获取/补齐实时60分钟K线，验证收线、缺口、09:30记录和复权基准。
2. 同一信号核心在显式已闭合K线上运行（当前历史引擎仍排除今日，不改变本版本）。
3. 独立持久化策略事件和订阅起点，用股票＋周期＋形态＋规则版本去重。
   首次启动只建立基线，不补推过去的历史事件；重启可继续去重。
4. 统一通知载荷传递上述来源字段，通知中心及桌面标题均显示【55线】，
   同时注明周期、确认时间、依据与失效条件；观察通知不带成交操作。
5. 历史补录、数据延迟/缺失或未收线时不得冒充当前确认信号推送。

本次仅增加来源展示和载荷字段，未启用实时采集、订阅或任何新增通知。
