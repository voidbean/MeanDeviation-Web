# 多周期55线：第一阶段（历史研究预览）

## 使用

重启应用后，查询A股个股，在原有近20日K线图上方可见“多周期55线”。
选择日线、60分钟或15分钟，点击“获取 / 更新”。打开页面和切换周期只读取
缓存，不消耗Tushare额度；首次获取需要点击按钮。不同股票/周期之间也至少
间隔90秒。频控、权限和网络错误不会覆盖已有成功数据。

## 实现与边界

- 官方 `daily` / `stk_mins` 获取原始周期，不自行聚合。
- `ts.pro_bar(api=安全适配器, adj='qfq', ma=[5,10,20,55,233])`
  负责复权和MA计算；目前沿用SDK两位小数精度。
- HTTPS访问官方API。优先系统curl（凭据经stdin，不经argv），无curl时使用
  requests。禁止输出原始响应、请求体和异常中的Token。
- 适配器把分钟请求的日期转换为复权因子接口所需的YYYYMMDD，并验证每个
  K线日期都存在有效因子；不允许SDK静默填补缺失因子。
- 日线请求600个自然日，分钟线240个自然日，最晚请求到上海时间昨日。
  返回不足55/233根时对应MA为空；不填造缺失K线。
- 校验代码、时间范围、重复时间、OHLC、非负量额、非有限数、截断上限。
  成交量统一为股，成交额统一为元。原始接口09:30记录保留，待对照交易软件。
- `kline55_cache`独立存储整个前复权快照（含基准日），成功后原子替换，
  不合并不同复权基准的历史数据，不修改daily_records或intraday_snapshots。
- `GET /api/kline55?code=600000&period=D`只读缓存；
  `POST /api/kline55/refresh?code=600000&period=D`显式更新。
- 仅支持A股个股，暂不处理ETF/指数。
- 全局持久化90秒节流只是保守起点，不代表已确认账户额度。

## 历史信号（第二阶段）

已增加日线NEW_TREND、日线→60分钟PULLBACK_ENTRY的历史规则复核，详见
[规则与限制](ma55-signals.md)。每次读取缓存时纯本地计算，不增加行情调用。
图表缓存中的 `signals_enabled: false` 为旧的执行开关，继续表示不启用实时交易信号；
独立 `analysis` 返回历史事件和阶段，`notifications_enabled` 保持false。

仍未启用实时刷新、策略评分、批量扫描或交易通知，也不进入AI提示词或盯盘执行规则。
分钟边界、开盘记录口径与交易日历覆盖仍需进一步核验；不满足条件时明确阻止确认。

纳入普通自动测试。所有测试凭据均不打印。
